# ARPipe Project Memory Vault

ARPipe is an annual-report extraction pipeline designed to reliably obtain the correct MD&A section from Indian corporate annual reports.

---

## Canonical Memory Index
- [[00_MASTER_LOG]] — Comprehensive chronological trajectory of all experiments and findings
- [[01_CURRENT_STATE]] — Active phase, last completed task, verified facts, and blockers
- [[02_DECISIONS]] — Architectural, methodological, and governance decisions
- [[03_EVIDENCE_REGISTER]] — Formal register of all claims and their evidential status
- [[04_WORKTREE_REGISTER]] — Registry of all worktrees, paths, branches, and commit SHAs
- [[05_OPEN_QUESTIONS]] — Active research questions, ambiguities, and hypotheses
- [[06_NEXT_TASKS]] — Prioritized roadmap starting from post-R1 diagnosis

### Specialized Directories
- **`experiments/`**: Detailed records for all historical initiatives (`Step_0`, `Step_0A`, `Step_0B`, `Diagnostic_Base_Sufficiency_Check`, `P-B1`, `P-B3`, `P-B4`, `P-B5`, `P-B7`, `P-M1`, `P-M2.1`, `P-M2.2`, `P-M3`, `P-M4`, `P-M5`, `P-C0`, `P-C0R`, `R1`).
- **`protocols/`**: Mandatory operational rules (`01_WORKTREE_SAFETY`, `02_EVIDENCE_AND_EPISTEMOLOGY`, `03_ACQUISITION_AND_TELEMETRY`, `04_CORPUS_AND_VALIDATION`).
- **`evidence/`**: Pointer indexes to frozen reports and raw diagnostic artifacts.

---

## Source Hierarchy
1. Git history and committed code
2. Frozen, hash-verified experiment reports and artifacts
3. This memory vault
4. Chat/session logs

---

## Core Operational Rule
> **ONE SESSION = ONE WORKTREE = ONE TASK.**
> Never silently convert INFERENCE or UNKNOWN into FACT.
